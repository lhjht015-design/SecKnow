## 说明

- 适配层把 pwntools 放进常驻 WSL worker，payload 构造与执行都在 worker 内完成；
- 启动成本（约首次加载 pwntools）单独统计，不计入单题耗时；
- 自研臂与 v030 相同，题目与偏移候选完全一致。

## 稳定性

三组随机种子各跑一遍，结果一致（自研 3/4、一次性 4/4、适配层 4/4）。

## 边界与解读

- 适配层的收益有两块：
  1) 多指令 gadget：P3 的 `pop rsi; pop rbp; ret` 自研扫描漏检，适配层能找到；
  2) 执行方式：worker 常驻，payload 构造与尝试都在同一个 WSL 进程内完成，
     不再每次尝试起一个 `wsl -e`（自研约 140 ms/次）。
- 一次性调用（每道题起一个 wsl 进程）也能解 4/4，但每题多一次进程与 pwntools 启动；
  适配层把这一成本摊到初始化（约 0.3 s）。
- 适配层只在求解侧使用：产品 API 仍然不执行目标程序；
  入口、后门定位、保护闸门与验证结论仍由自研部分给出。
- gadget 搜索是分析操作，不执行；`run` 仅由实验/求解脚本显式调用。
