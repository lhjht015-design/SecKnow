一、应用核心框架

1.1 平台定位与整体架构

SecKnow 是一个面向实验室内部的、以语义向量检索为核心的智能知识管理平台。平台将权威教材、研究报告、实战笔记等非结构化文档转化为高维语义向量，并围绕向量数据库构建三大知识分区（网络空间安全、人工智能、密码学），实现精准的语义级检索与知识沉淀。

平台同时支持在线协作模式与离线单机模式，兼顾实验室日常学习场景与赛事离线环境（CTF、密码竞赛等）的双重需求。所有推理引擎均采用非大模型的传统语义算法，保证在赛事环境中合规使用。

1.2 核心逻辑链路

平台核心处理流程分为「文档入库链路」与「查询检索链路」两条主线，共同支撑平台的知识管理与智能检索功能。

【文档入库链路】

文档上传：用户提交文档（PDF/Word/Markdown/代码文件等）

文本预处理：分段清洗、语言规范化、去噪

语义切块：按滑动窗口或语义边界自动分块（Chunk）

向量化编码：使用离线语义编码模型（如 SBERT 中文模型）生成向量

恶意梯度审查：与知识库初始方向向量进行余弦相似度检验，过滤偏离阈值的块

去重入库：MinHash 指纹去重后写入向量数据库（Qdrant/Milvus）及原文索引库

【查询检索链路】

用户输入自然语言查询或代码片段

查询向量化：使用相同编码模型将查询编码为向量

ANN 近邻检索：在目标分区向量库中执行近似最近邻搜索（HNSW/IVF-PQ）

结果召回与重排：基于 BM25 稀疏检索做混合重排，返回 Top-K 原文片段

代码风险扫描（安全分区）：将代码切片与风险函数向量库比对，输出风险点及参考资料

结果展示：返回原文段落，附交互按钮（已解决 / 未解决 / 不提交）

1.3 三大知识分区

平台设立三个相互独立、分别维护的知识分区，每个分区拥有独立的初始方向向量基准（由权威资料生成），用于后续恶意梯度检测。

1.4 双模式运行机制

平台提供「在线模式」与「离线模式」两种运行形式，满足不同场景需求：

在线模式

用户经管理员审核注册后，通过 Web 端访问平台。后端集中维护向量库与用户数据，支持多人协作、评论区互动、积分排行榜等社区功能。所有推理与检索在服务端完成，用户无需关心环境配置。

离线模式

用户可按分区选择性下载知识库快照与轻量级推理 UI 到本地机器，实现无网络环境下的语义检索。离线包含机器码绑定校验，限定单设备激活，防止知识库未授权扩散。离线推理全程使用传统语义匹配算法（SBERT + FAISS/Qdrant 本地库），无需调用任何大模型，符合赛事对 AI 工具使用的合规要求。用户可自主选择是否加载评论区内容。

二、应用的意义及目的

2.1 背景与痛点

当前实验室的知识积累方式较为分散：学习笔记存放于各人电脑，优质资料缺乏系统归档，CTF 赛题的解题经验往往随时间流失。新成员难以快速找到权威参考资料，老成员的经验也无法有效传承。为此，我们计划建设一套统一的知识管理与检索平台，以结构化手段沉淀实验室知识资产，提升整体科研与竞赛战斗力。

2.2 核心目标

SecKnow 平台的建设具有以下核心目标：

（1）提升实验室硬实力

通过系统性地构建网络空间安全、人工智能和密码学三大专业知识库，实验室成员可以在一个统一的平台上高效地查阅权威资料、积累实战经验、学习最新技术动态，从而在科研和竞赛中保持持续的技术领先优势。知识的规范化沉淀，让实验室的整体学术水平得以有据可查地持续提升。

（2）营造线上学习氛围

平台内置积分排行榜、评论互动区、题目解决率公示等社区功能，让学习本身具备游戏化激励效果。成员在检索解题思路的同时，可以看到同学的学习进度与点评，形成良性的互动学习氛围，使学习不再是孤立的个人行为，而成为全实验室共同参与的集体活动。

（3）统筹日常刷题与训练安排

平台通过对每位成员的「已解决率」「未解决次数」等指标进行统计，使管理员可以直观了解各成员的学习状态与薄弱环节，从而有针对性地安排题目、制定学习计划。预警机制的引入，使管理员可以及时发现知识库中亟需补充或修正的内容，保持知识库持续鲜活。

（4）冲击国内外重要赛事

平台专门针对 CTF、密码学竞赛等赛事场景进行优化设计。离线模式保证赛事现场可以合规使用；代码风险扫描功能为 Web 安全类题目提供辅助；密码学分区的权威资料则为密码竞赛的快速查阅提供支撑。我们希望以 SecKnow 为基础，系统性地提升实验室在各类信息安全竞赛中的成绩，逐步建立竞赛优势。

（5）构建可持续成长的学习平台

不同于静态文档库，SecKnow 是一个可持续成长的动态知识系统。通过用户上传、管理员审核、恶意梯度检测等机制，知识库将随着实验室成员的使用不断丰富和完善。每一次学习交互、每一条评论，都将成为平台的知识增量，形成知识的良性复利效应。

四、分模块设计

本章按功能域将平台拆解为以下七个核心模块，每个模块说明其职责边界、对外暴露的接口及依赖关系，以指导团队分工开发。

4.1 文本处理自动化模块（Text Processing Module）

职责：负责将原始文档转化为可入库的标准化文本块。接收多格式文件（PDF、DOCX、Markdown、TXT、代码文件），执行清洗→分块→去重→编码的完整流水线，输出向量及原文元数据。

4.2 恶意梯度检测模块（Safety Guard Module）

职责：在文档正式入库前执行安全审查，通过与各分区初始方向向量的余弦相似度比对、统计离群检测、内容分类校验等多重手段，拦截与分区方向严重偏离或含有恶意内容的文档块。

4.3 向量数据库模块（Vector Store Module）

职责：统一管理三个分区的向量数据与原文存储。提供向量写入、近似最近邻检索（ANN）、混合检索（向量 + BM25）等标准接口，屏蔽底层数据库差异（在线使用 Qdrant，离线使用 FAISS）。

4.4 推理模块（Inference Module）

职责：接收用户查询请求，编排检索流程，返回格式化结果。区分「语义问答检索」和「代码风险扫描」两种查询模式。所有推理均在无大模型依赖的前提下完成，保障离线合规性。

4.5 后端交互模块（Backend API Module）

职责：提供统一的 RESTful API 层，处理用户请求路由、身份认证、权限校验、任务调度等后端核心逻辑。连接前端 UI 与各内部功能模块，保障系统整体的数据一致性与安全性。

4.6 UI 模块（Frontend UI Module）

职责：提供用户操作界面，包含搜索页、文档上传页、评论区、排行榜、管理员控制台等视图。在线端为 Web SPA，离线端通过 Tauri 打包为桌面应用。

4.7 预警与用户管理模块（Alert & User Module）

职责：统计用户行为指标，触发预警并通知管理员；管理用户注册审核、权限体系、积分排行榜；同时提供机器码绑定校验逻辑供离线端使用。

建议按以下三个阶段推进项目，优先保障核心功能的可用性，再逐步叠加增强功能。

六、补充说明与注意事项

安全合规性

离线端严禁集成任何在线大模型 API 调用（OpenAI、Claude、通义等），推理逻辑限定为本地 SBERT + FAISS 链路，确保在 CTF 等赛事现场使用的合规性。

数据安全

知识库内容属于实验室内部资产，在线端须启用 HTTPS，向量数据库不对公网开放；离线端机器码绑定防止知识库二次分发。

扩展性预留

后端 API 模块与推理模块之间保留「大模型接入接口」占位符，待后续规划明确后可低成本接入 LLM 完成自动解题、知识总结等高级功能，而不影响现有系统稳定性。

管理员权限分级

建议区分超级管理员（可设置新管理员、删除知识库分区）与普通管理员（可审核用户、编辑知识块、查看预警）两级，降低误操作风险。

评论区中间态阅读计数

为准确统计阅读量（区分于「已解决」和「未解决」），建议在结果展示时设置 5 秒以上驻留检测，用户停留超过阈值才触发「中间态」计数，过滤误点行为对预警指标的干扰。
