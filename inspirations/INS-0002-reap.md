## 核心思想

把多跳推理从**线性管道**重构为**动态状态驱动的循环**，显式维护两样东西：

1. **子任务计划** $\mathcal{P} = \{(id_i, q_i, deps_i)\}$ —— 由 Decomposer 生成，带依赖关系
2. **结构化事实列表** —— 由 Fact Extractor 从检索内容里抽取，而不只是抽答案

然后 SP（子任务规划器）与 FE（事实提取器）**递归协作**：
SP 看全局状态决定下一步动作，FE 执行检索并产出事实与"潜在线索"，
两者互相反馈，形成可自纠正的推理循环。

## 与 SAG2 的对比

| | SAG2 | REAP |
| --- | --- | --- |
| 跳的驱动力 | 词扩展（新检索词） | 结构化子任务 + 依赖 |
| 是否需要 LLM | 只需要判官 | **需要 LLM**（论文用 Llama-3.1-8B） |
| 离线可行性 | 架构离线，JEV 需替换 | 可用本地 8B 模型，但违背"不用大模型"约束 |
| 对我们的价值 | **主路线**（离线、轻量） | 备用路线（若将来允许 LLM） |

## 关键洞察（可直接借用，不必用 LLM）

论文指出的痛点值得我们借鉴：

> 「检索内容利用不足——模型倾向仅提取直接答案，忽略对最终解答关键的**潜在线索**。」

我们的 v003 验证闸门恰好只检查「载荷是否在证据里」，没有检查「线索是否被用上」。
一个纯确定性的改进：在证据里检测**未被任何步骤引用的高相关段落**，
提示用户「这些证据你没有用到」。这不需要 LLM。

## 迁移方案（若启用 LLM）

- SP 用本地 qwen3:8b，输出结构化 JSON 的子任务计划
- FE 用同一模型从每轮检索结果里抽事实
- 因为本地 8B 的可靠性问题（见 LAW-0002 / EXP-0001），必须**保留 v003 的确定性闸门**
  作为最终放行条件——LLM 只负责提计划，不负责宣布成功

## 结论

**暂不实现。** 当前约束是"离线 + 不用大模型"，REAP 的核心价值依赖 LLM。
先等 SAG2 式多跳（v005）的实测结果；如果词法多跳不够，再考虑引入本地 LLM 的 REAP 变体。
