topic: 黑盒反解接入契约单元库——能力不变，但策略变成可组合、可拒绝、可验证的单元
hypothesis: 把 v019 的四类反解策略拆成带 accepts/produces/guard 的契约单元后，
            同一套规划器仍能解同样的题，而且路径与拒绝原因更清楚。
experiment:
  - 复用 EXP-0017 的 8 个挑战脚本（P1–P5 正样本，N1–N3 负样本）。
  - 单元库 8 个：
      probe_facts           oracle        → facts
      classify_structure    facts         → structure（bytewise/permutation/dense）
      invert_bytewise_affine structure(bytewise)  → plain
      invert_bytewise_table  structure(bytewise)  → plain
      invert_permutation     structure(permutation)→ plain
      invert_gf2             structure(dense)      → plain
      solve_prefix_checker   checker       → verified
      verify_plain           plain         → verified
  - 规划器：DFS + 回溯；单元按代价从低到高排列；单元不适用时抛 Refuse，
    规划器继续试下一个候选；所有候选最终都要过 verify_plain（重新加密 == 原密文）。
  - 结果（连续 2 次一致）：
      P1 → probe_facts → classify → invert_bytewise_affine(拒绝) → invert_bytewise_table → verify
      P2 → … → invert_bytewise_affine → verify
      P3/P4 → … → invert_gf2 → verify
      P5 → solve_prefix_checker
      N1 → probe_facts 拒绝 not_length_preserving
      N2 → invert_gf2 拒绝 structure_unknown
      N3 → probe_facts 拒绝 nondeterministic
    正样本 5/5，负样本 3/3，总探测数 7484——与 v019 单体实现完全相同。
result:
  - **四个关键点**：
    1. **契约化没有增加能力，也没有增加开销。** 总探测数与 v019 一字不差；
       差别在于每一步现在都有类型、guard 与显式拒绝，可被单独测试和复用。
    2. **"逐字节"是一个结构标签，不是一个单元。** 仿射与建表是同一状态上的
       两个并列候选：仿射更便宜（4n 次探测），先试；它抛
       `affine_not_applicable` 不是错误，而是"换建表"的信号（P1 正是这样走的）。
       这与 v009/v010 的"多单元召回 → 逐个执行 → 失败剪枝"是同一机制。
    3. **执行验证保持唯一出口。** 四个反解单元都只产出 `plain`，必须再进
       `verify_plain`；任何策略都不能绕过"重新加密 == 原密文"。
    4. **拒绝原因分层。** 探测层（nondeterministic / not_length_preserving）、
       结构层（structure_unknown）、反解层（not_bijective / not_invertible /
       verify_failed）各自有明确信号，不会把"判不出"混成"解不出"。
  - **能力边界与 LAW-0023 完全一致**：契约化不会让非线性构造变得可解。
    它只是让已有的四类策略成为库里的一等公民。
conclusion:
  - 单元库的价值不只是"召回代码"，更是**把决策点显式化**：
    吃什么、吐什么、什么条件下适用、不适用时怎么拒绝。
    黑盒反解接入后，与 encoding / RSA / pwn 单元共享同一套规划与验证机制。
  - 规划器用 DFS + 回溯而不是穷举所有分支，便宜的策略先试，
    失败才换下一个；实测既保持了单体实现的探测数，又保留了多候选的鲁棒性。
