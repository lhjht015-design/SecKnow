```yaml
topic: ret2dlresolve 要改 DT_STRTAB，不是伪造 relocation；worker 的全局 arch 要随二进制复位
experiment:
  - dlresolve-gets（XDCTF 2015，i386，no-relro）：
      pwntools 的 Ret2dlresolvePayload 被 loader 以
      `r_info` 类型不符拒绝（`_dl_fixup` 断言失败）。
      改为参考路线：把 `.dynamic` 里的 DT_STRTAB 指向 .bss 上的伪 dynstr，
      原 dynstr 中 `read` 替换为 `system`；
      ROP 三次 read 写入新 strtab 指针 / 伪 dynstr / `/bin/sh`，
      再跳 `read@plt+6` 触发解析，0.56 秒拿到 shell。
  - 产品链：32 位、非 full RELRO、导入 read → ret2dlresolve（needs-execution）。
  - 过程 bug：常驻 worker 在 SROP 之后把 context.arch 留在 amd64，
    下一条 i386 链报 `Invalid arch/bits combination: i386/64`；
    修复为 `_elf()` 每次切换二进制时同步 `context.arch` 与 `context.bits`。
  - 结果：第四轮回归 3/4（goodluck、srop、dlresolve），2 次一致。
result:
  - **dlresolve 的合法路径是改 strtab，不是造 relocation。** loader 会校验
    relocation 类型；把符号名表指向伪 dynstr 才能让解析器解析出 system。
  - **常驻 worker 的全局状态是隐式依赖。** context.arch/bits 必须跟着当前
    二进制复位，否则跨架构连续调用会静默失败。
  - **参考实现能跑通时优先复用其机制。** pwntools 的高层封装失败不代表
    思路错了，换底层机制反而最直接。
conclusion:
  - ret2dlresolve 单元按“改 DT_STRTAB + 伪 dynstr + read 链 + plt+6”实现；
    第四轮仅剩 partial-gets（镜像不匹配）。
```
