source: 实验
topic: ret2libc 可单元化，但 PLT 桩有两种形态，libc 版本校验只能是"便宜的怀疑"
hypothesis: 泄漏一个 libc 运行时地址，用题目给的 libc 偏移算出基址，就能调 system("/bin/sh")。
experiment:
  - 新靶场 `vuln3.c`：`read(0, buf, 512)` 溢出，无 canary、无 PIE，
    只隔离"libc 版本识别 + 两阶段利用"这一个变量。编译 `vuln3`，另用
    `-fno-plt` 编 `vuln3_noplt` 作负样本。`libc.so.6` 从系统拷贝随实验保存。
  - 新增三个单元：
      `plt_stub`     从 `.rela.plt` 与 `.plt` / `.plt.sec` 解析导入函数的可调用地址
      `libc_offsets` 从给定 libc 取 puts / system 符号偏移与 "/bin/sh" 虚拟地址
      `leak_libc`    发 stage1、解析 6 字节泄漏、算基址并校验页对齐
  - stage1: `padding + pop_rdi + puts@got + puts@plt + main`（回到 main 保持进程活着）
    stage2: `padding + ret(对齐) + pop_rdi + base+binsh + base+system`
  - 结果（连续 3 次稳定）：
      L1 正常 ret2libc                → ✓ 解出（约 1.0 s）
      N1 故意用错 puts 偏移（模拟版本不匹配） → ✓ 如实拒绝（`libc_mismatch`）
      N2 `-fno-plt` 编译、无 PLT 桩         → ✓ 如实拒绝（`plt_stub_missing`）
result:
  - **五个关键点**：
    1. **现代 Ubuntu 的可调用桩在 `.plt.sec`，不在 `.plt`。** 默认 `-z ibtplt` 链接后，
       `.plt` 只剩 resolver 入口（`push <index>; jmp plt0`），每个导入函数的真正桩是
       `.plt.sec` 里的 `endbr64; bnd jmp [rip+X]`。编译器 call 的是后者。
       只解析 `.plt` 会把桩地址报成 `.plt` 入口——它仍能工作，但**用桩地址去匹配
       代码里的 call 目标会全部失配**，进而把"调用了 read 的函数"认错，偏移推导失败。
       正确做法：解析 `.plt.sec` 中 `jmp [rip+X]` 的 X 反推 GOT 项，与 `.rela.plt`
       的 `r_offset` 对齐。
    2. **capstone 的渲染和直觉不一致。** `bnd jmp` 的 mnemonic 是 `"bnd jmp"`（带空格），
       不是 `"jmp"`；`push 0` 的 op_str 是 `"0"`，不是 `"0x0"`。按 `"0x"` 前缀判断
       会一个桩都解析不到，现象是 `symbol_not_in_plt`——错误信息看起来像"符号不存在"，
       实际是解析器写错了。
    3. **页对齐只是"便宜的怀疑"，不是版本匹配的证明。** 正确 libc 的偏移必然把基址
       落在 0x1000 边界；用错偏移大概率不齐，所以它能在几乎零成本下拦住大部分错误。
       但若错版本与正确版本的 puts 偏移之差恰好是 4 KB 整数倍，基址仍会对齐，
       校验通过而利用会崩。真实场景要**以题目附带的 libc 为准**，并靠执行结果反证。
    4. **`/bin/sh` 的偏移必须从文件偏移换算成虚拟地址。** 直接在 ELF 文件里搜到
       `/bin/sh` 拿到的是文件偏移；需要找到包含它的 PT_LOAD 段，
       用 `p_vaddr + (file_offset - p_offset)` 换算。直接拿文件偏移当偏移用，
       地址会指向错误的位置。
    5. **没有 PLT 时要如实拒绝。** `-fno-plt` 的二进制没有 `.plt` / `.rela.plt`
       （只有 `.got.plt` 与 `R_X86_64_GLOB_DAT`），拿不到 `puts@plt`。
       返回 `plt_stub_missing`，不要退化成"猜一个地址试试"。
  - 耗时：正样本约 1.0 s（含两次跨 WSL 交互）；两个负样本都在 200 ms 内返回。
conclusion:
  - ret2libc 的本质是**信息流 + 版本匹配**：先泄漏一个已知符号的运行时地址，
    再用同一份 libc 的偏移算出基址。单元化可行，L1 真实拿到 flag。
  - 最大的风险不是 ROP 拼装，而是 **libc 版本**。页对齐校验只能证伪一部分错误，
    不能证明匹配；这条必须写进单元契约，避免把"算出了基址"当成"版本对了"。
  - 与 LAW-0019 一致：泄漏与利用必须同进程；stage1 必须回到 `main` 而不是退出，
    否则第二阶段没有进程可用。
next: 三保护全开（canary + PIE + ret2libc）的组合验证、stripped/-O2 二进制上的
      ret2win 复测（真实题常去符号）、libc 数据库式的多版本候选匹配。
