topic: 入口由附件建立，不由题面措辞建立——后缀/魔数/内容三条路，策略交给结构分类
hypothesis: 去掉"题面必须出现加密脚本/S盒/Feistel"的依赖后，入口仍能自动建立，
            并且 Python 脚本、zip 内脚本、ELF 可执行、文本数据都能被正确路由。
experiment:
  - 附件识别：
      PK\x03\x04            → zip（递归看成员，深度 ≤2）
      \x7fELF               → ELF（WSL 内逐次执行，stdin → stdout）
      后缀 .py/.src          → Python
      内容含 def enc/check   → Python（与后缀无关）
      可打印文本             → 数据（按形态加召回提示）
      其它                   → attachment_unknown
  - 两个 oracle 后端：
      AutoOracle  载入 Python 脚本，握手 MODE enc/check/none
      ElfOracle   在 WSL 里把可执行文件当黑盒，每次探测一个进程
  - 入口一旦由附件建立，**所有策略单元都可用**，选择交给依赖矩阵与 guard；
    题面召回只在"附件是数据"时负责选文本单元。
  - 文本附件按形态加提示：长 hex → XOR，长 base64 → Base64。
  - 结果（连续 3 次一致）：
      A1 .src 脚本（题面不提技术名） → python → 解出，153 次探测
      A2 改名 .dat                  → python（按内容）→ 解出，178 次
      A3 zip 内脚本                 → python（递归）→ 解出，4450 次
      A4 ELF 变换程序               → elf → 解出，117 次，约 1.8 s
      A5 文本 hex                   → text → xor_single_byte
      A6 文本多层 Base64            → text → base64_chain
      N1 随机二进制                 → attachment_unknown
      N2 无 enc/check 的脚本        → no_enc_or_check
      N3 zip 内无可用成员           → zip_no_usable_member
      N4 ELF 校验器                 → not_length_preserving
    正样本 6/6，负样本 4/4，平均 270 ms/题。
result:
  - **四个关键点**：
    1. **后缀可以被伪造，内容与魔数不会。** A2 把 Python 脚本改名成 `.dat`，
       识别仍然正确——判据是 `def enc/check` 这个内容特征，不是扩展名。
       反过来，后缀优先级要低于魔数：先看 PK/ ELF，再看后缀，最后看内容。
    2. **zip 是容器，不是类型。** A3 的正确做法是解出成员后递归识别，
       而不是把 zip 当成"压缩数据"直接放弃。
    3. **ELF 后端让"编译后的程序"与脚本同权。** A4 的变换是 C 写的，
       走 WSL 逐次执行，117 次探测约 1.8 s。代价明显高于脚本（同题 153 次探测
       约 0.3 s），但方法完全一致：probe_facts → classify → invert → verify。
    4. **文本附件不建 oracle，按形态路由。** A5/A6 题面没有任何技术词，
       靠"长 hex / 长 base64"两个形态提示就把 XOR 与 Base64 单元召回了。
  - **诚实边界**：
    - ELF 后端假设程序是"stdin → stdout"的无状态变换。带参数、需要文件、
      或多轮交互的二进制不适用；ELF 校验器也只能靠"输出长度不随输入变化"
      拒绝，没有真正的前缀爬坡接口。
    - 每次探测起一个进程，table 策略在 ELF 上会是 256n 次进程启动；
      本实验只让 ELF 走仿射（4n），未在大二进制上压测。
    - zip 递归深度限制为 2；更深的嵌套会返回 zip_no_usable_member。
    - 识别是启发式的：一个正文里恰好含 `def enc` 的文本会被误判成脚本。
      误判的代价是尝试建立 oracle 失败或 probe_facts 拒绝，不会伪造答案。
conclusion:
  - LAW-0025 的遗留问题是"黑盒入口依赖题面措辞"。本实验把入口改成**看附件**：
    后缀/魔数/内容三条路覆盖了比赛中常见的"给脚本、给压缩包、给二进制、
    给一段密文"四种形态。
  - 入口建立后不再需要题面提示，策略由结构分类选择；这与"召回的文本线索"
    解耦，正是面对"主办方自己实现逻辑"时最需要的性质。

      大二进制上压测 table 策略的进程启动成本；按文件大小/熵做更稳的启发式。
