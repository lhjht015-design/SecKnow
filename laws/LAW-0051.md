  - 新增 syscall 链：无 system 时按位数选 gadget 构造 execve("/bin/sh",0,0)。
    bamboofox ret2syscall（静态 32 位）真拿到 shell，偏移 112。
  - 新增格式化字符串单元：
      偏移探测：发送 `AAAA.%p...`，用 0x41414141 找到参数位置；
      泄漏：按偏移读栈/内存；
      写入：pwntools fmtstr_payload 构造 %n，目标地址从程序输出里取
            （同一进程内读取，避免 ASLR 变化）。
  - 真实赛题回归（ctf-wiki，全 32 位）：
      ret2text / ret2libc1 / ret2syscall / leakmemory / overwrite 解出 5 题；
      contacts（canary + 多阶段堆布局）拒绝；pwn3（题目特有口令变换）不支持。
    连跑 3 次结果一致。
result:
  - **两类空缺补上后，真实覆盖从 2/5 到 5/7。** 提升来自“调用点/参数构造”
    与“偏移探测 + %n”，不是执行能力。
  - **格式化字符串的关键是同一进程内完成“读地址 → 写地址”。** 分两次启动进程时
    栈地址随 ASLR 变化，写入必失败；偏移可以跨进程复用，地址不能。
  - **题目特有逻辑仍是硬边界。** pwn3 的口令由硬编码字符串逐位减一得到，
    这不是格式化字符串单元能推出来的；canary + 堆布局的 contacts 需要多阶段链。
  - **解出判据要贴合题目。** leakmemory 没有 flag，判据是成功泄漏多个地址；
    overwrite 的判据是程序自己的成功输出，而不是“进程没崩”。
conclusion:
  - 新增单元应按“原语”拆分（偏移 / 泄漏 / 写 / syscall），
    由链选择器按题目条件组合；真实赛题的剩余缺口集中在多阶段布局与题目特有逻辑。
