topic: SROP 的门槛是栈地址泄漏，不是帧构造；极简二进制用 read 返回值做 rax
experiment:
  - srop-smallest（360 春秋杯 2016）只有 `read(0,rsp,0x400); ret`：
      连发 3 个 start 地址让程序停在 read；
      发 1 个字节 `\xb3` 改写返回地址低字节为 start+3（跳过 xor rax），
      read 返回 1 → rax=1，触发 write(1,rsp,0x400) 泄漏栈地址；
      构造 read 的 sigreturn 帧（rax=15 触发 rt_sigreturn），
      第二帧设置 execve("/bin/sh")，再次触发；
  - worker 的 op=srop 固化流程，2.0 秒拿到 shell；
  - 产品链：64 位、指令数 ≤ 20 的极小 syscall 二进制给出 srop（needs-execution）。
  - 第四轮回归从 1/4 提升到 2/4（goodluck + srop-smallest），连跑 2 次一致。
result:
  - **SROP 的难点是拿到栈地址。** 帧本身是确定性的；没有栈地址就没有可写的帧位置。
  - **read 的返回值就是现成的 rax。** 发 1 字节得到 rax=1，
    配合低字节改写即可把 read 变成 write，是极简二进制的通用小技巧。
  - **极简二进制要先识别再套模板。** 指令数极少 + 只有 syscall 时，
    优先走 SROP，而不是继续找 pwn 链。
conclusion:
  - SROP 单元按“泄漏栈 → 读帧 → 触发 rt_sigreturn → execve”固定流程实现；
    剩余 deep 缺口是 partial overwrite 与 ret2dlresolve。
