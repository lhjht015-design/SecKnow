date: 2026-11-11
source: 实验
topic: 时序侧信道爬坡可行，但代价结构决定了算法必须"基线 + 早停"，不能全字符集扫描
hypothesis: 校验器只泄露耗时（stdout/退出码恒定）时，逐字节测量 + 频率序早停
            仍能恢复完整输入；信号太弱时如实拒绝。
experiment:
  - 靶场（`experiments/EXP-0022/`）：
      chal_timing.c         ELF，每匹配一字节 sleep 6ms，输出恒 "wrong"，退出码 1
      p7_timing.src         Python，每匹配一字节 sleep 2ms，返回常量 0
      chal_timing_const.c   恒定 sleep 5ms，与输入无关
      chal_timing_faint.c   每匹配一字节只 sleep 0.2ms（埋在进程启动噪声里）
  - 接口检测新增 timing：
      对 100 个探测测耗时；若峰值 − 中位数 > 阈值（ELF 4ms / Python 2ms）
      且峰值 > 1.5×中位数，再对峰值输入复测 3 次确认。
  - 爬坡单元 `solve_timing_checker`：
      每个位置先用 0x01（必不匹配）测基线；
      按"flag{}_ + 字母频率序 + 数字 + 大写 + 标点"扫描，耗时明显高于基线即确认；
      确认通过就早停，不再测剩余字符；
      每步要求"确认值 − 基线"大于 0.5×单字节延迟，否则 timing_signal_weak；
      最后把完整候选与"首字节打错"的输入各测 3 次，差值需 ≥ 0.5×len×delay。
  - 结果（连续 3 次一致）：
      T1 ELF timing（flag{t1ming}）      → 解出，约 11 s，387 次探测
      T2 Python timing（flag{t1m3}）     → 解出，约 3 s，377 次
      R1 ELF 数字前缀（v023 回归）        → 解出，419 次
      N1 恒定 sleep 5ms                  → no_prefix_signal
      N2 每字节 0.2ms                    → no_prefix_signal
    正样本 3/3，负样本 2/2，平均约 4.1 s/题。
result:
  - **五个关键点**：
    1. **时序的成本结构是平方级的。** 每次探测都要重放已知前缀，位置 p 的
       一次探测耗时 ≈ p×delay。第一版按完整 95 字符集扫描 + 5 次确认，
       27 字符的 Python 题跑了 **447 秒**。这不是参数问题，是算法问题。
    2. **基线 + 早停把平方级常数压下来。** 每个位置先测 0x01 得基线
       （p×delay + 开销），再按频率序逐个试；命中即停。T2 从 447 s 降到 2.8 s。
       仍保留平方项，所以演示密钥缩短到 11–12 字符——方法验证不依赖长密钥。
    3. **检测必须复测峰值。** 只凭一轮 100 次探测的峰值，N2 的 0.2ms 信号
       曾被一次噪声尖峰误判成 timing；对峰值输入复测 3 次取中位数后，
       N2 正确回到 none。检测和爬坡都要"再确认一次"。
    4. **位置级 margin 是时序版的执行验证。** 每个字符都要求
       "确认中位数 − 基线"超过 0.5×delay；达不到就 timing_signal_weak。
       这保证噪声不会把错误字符写进结果。
    5. **结束验证要检查整串长度。** 完整候选 vs 首字节打错的输入，
       耗时差应约等于 len×delay；不足则 timing_verify_failed。
       这弥补了"只验证最后一个字节"的漏洞。
  - **诚实边界**：
    - 要求校验器逐字节比较且**匹配越多越慢**；常数时间比较、先哈希再比较、
      或一次性比较的校验器不受影响，会如实返回 no_prefix_signal。
    - 单字节延迟必须显著高于测量噪声：ELF 每次探测起一个进程（约 4ms 噪声），
      实测需要 ≥6ms/字节；Python 进程内调用噪声小，2ms 足够。
    - 代价仍随已知前缀长度增长；超长 flag 需要分段或更低噪声的测量方式。
conclusion:
  - 时序侧信道是 LAW-0027"前缀接口"的第四种信道：没有显式输出，
    但耗时本身构成一个有序信号。检测、归一、爬坡、验证的骨架完全复用，
    只是把 `oracle.call(x)->int` 换成 `oracle.time(x)->float`。
  - 这条路的可靠性来自"每步都比基线、每步都可拒绝"，
    而不是来自"测得准"。信号弱时返回明确原因，不硬猜。
next: 统计更稳的测量（多次中位数 + 预热）；分段处理超长输入；
      时间与数字/退出码多信道融合；在真实 stripped 校验器上压测。
