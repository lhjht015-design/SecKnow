topic: 真实 CTF 的解题链里，六成是题目特有逻辑，标准技术单元只能覆盖少数
hypothesis: 用 Des-CTF-Knowledge 里 1156 条真实攻击链，可以测出我们单元库的真实边界。
experiment:
  - 数据：`CTF大赛WP集合/articles/*.meta.md` 中带 `attack_chain` 的 **726 条**真实题解，
    共 **6795 个步骤**（人工写的分步思路，是本项目能拿到的最真实的真值）。
  - 方法：用可解释的关键词规则把每一步归入技术族（encoding / xor / rsa / pwn / reverse / sql …），
    再对照我们已实现的契约单元族。
  - 结果：
    | 指标 | 值 |
    | --- | --- |
    | 总步骤 | 6795 |
    | **无法归入任何标准技术族（题目特有逻辑）** | **4191（61.7%）** |
    | 可归类的步骤 | 2604 |
    | 其中落在我们已覆盖的族 | 1035（约 32% 的可归类步骤） |
    | 能由现有单元完整覆盖的整条链 | **81 / 726（11.2%）** |
  - 真实步骤里出现最多的族：pwn 635、reverse 304、encoding 287、hash 190、
    binary 187、block_cipher 174、sql 162、xor 145、image 126、rce 125、rsa 97、deserialize 94。
    其中我们目前只覆盖 encoding / binary / xor / image / rsa。
  - 抽查那 61.7%：内容是
    「写入 orw shellcode (openat+mmap+writev)」「sub_8001A8C 计算 a1=(a1>>6)&(a1>>2)」
    「torch.load('model.pth') 提 eval_cache 做 argmin 距离」
    「输入 0o57355（Bank×0o2000+addr-0o2000）按 ENTR 循环读 ROM」
    「把 smc 写回 PE 文件」……
    这些不是"没识别出来的标准技术"，而是**题目自己定义的逻辑**。
result:
  - 真实 CTF 的主体不是"标准技术的组合"，而是"在标准技术之上叠加题目特有的变形"。
    标准技术族只占约 38%，而这 38% 里我们目前覆盖约三分之一。
  - 这解释了为什么"在自家题库表现很好、到真实比赛就解不了"：
    自造题用的是标准技术的干净组合；真实题每一步都可能带一层自定义逻辑。
  - **检索/规划再好，也变不出库里没有的单元。** 覆盖率的上限由单元库决定，
    不由搜索算法决定。
  - 分类器本身也有误差：初版只识别出 28.7% 的步骤，补充规则后升到 38.3%。
    所以"61.7% 特有逻辑"是**上限估计**（真实值可能更高，因为有些被规则误收了）。
conclusion:
  - 应按**步骤数**而不是按"题的个数"来决定下一步补什么单元：
    优先 pwn（635）、reverse（304）、hash（190）、block_cipher（174）、sql（162）、rce（125）。
  - 对"题目特有逻辑"，唯一可行的路径是**新增单元**或**真正的程序综合**，
    而不是继续优化检索。这与 LAW-0011 的结论一致，只是在真实数据上量化了。
  - 报告这类覆盖率时，必须同时给出"分类器识别率"（本次 38.3%），
    否则会把"分类器没覆盖到"误当成"技术上不存在"（LAW-0007 的同类问题）。
next: 按步骤数补齐 top 5 缺口族的最小可用单元集，再用这批真实攻击链复测覆盖率。
