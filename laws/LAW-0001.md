```yaml
topic: 生成即结论——无验证链路必然产生"假能解"
hypothesis: 离线推理系统若把 LLM 的生成文本直接当作结论返回，则系统对自身能力的判断完全不可信；这与其模型规模无关。
experiment: 审阅 SecKnow 现有 answer/llm.py（92 行）。链路为 检索证据 → 拼 prompt → LLM 一次性输出 → 直接返回。全链路无任何可证伪环节。对照用户过往浙密杯解题系统：AI 每次声称"能解"，现场全部失败。
result: 该链路中，"能解"是 LLM 生成的文本，不是被任何机制验证过的结论。模型规模提升只会让"假能解"更流畅、更有说服力，不会降低其发生率。
conclusion:
  - 系统的能力断言必须来自可证伪的环节（执行结果、证据匹配、覆盖度计算），不能来自生成文本的自我描述。
  - 任何"能解/不能解"的对外输出，必须能回溯到具体证据编号或具体执行结果。
  - 弃答（证据不足）必须是一等公民输出，且其触发条件可测量。
next: 在 v002 中实现 verification gate：把"引用有效性 + 执行成功"作为回答放行的必要条件。对未能通过验证的回答强制降级为"证据不足 + 已知信息"。
```

**补充说明（供论文写作）**

这条规律的本质是一个**训练目标与部署目标错位**问题：LLM 的训练目标是生成"看起来正确的续写"，而系统的部署目标是"输出可执行的正确结论"。在无验证的链路中，前者的分布会在所有"不确定"的场合坍缩到最确定、最自信的表达方式——也就是"能解"。这与模型是否诚实无关，是解码目标的必然结果。
