id: LAW-0027

date: 2026-11-11
source: 实验
topic: ELF 校验器可以做成统一的前缀接口——三条信道归一成一个 score，检测不到就拒绝
hypothesis: 编译后的校验器只要能泄露"正确前缀长度"，就能像 Python 校验器一样
            逐字节爬坡；接口差异可以用 stdout 数字 / 带标签数字 / 退出码三种归一化吸收。
experiment:
  - 新增五个 ELF 靶场（`experiments/EXP-0021/lab/`）：
      chal_check_int       stdout 输出纯数字前缀长度
      chal_check_fmt       stdout 输出 "prefix=N"
      chal_check_exit      前缀长度编码在退出码里（0..255），stdout 恒为 "wrong"
      chal_check_nosignal  只回 "wrong"，不给任何进度
      chal_check_constant  输出恒为 "0"，数字存在但不随输入变化
  - 接口检测（`detect_elf_interface`）：对二进制做一组探测
      （空串 + 95 个可打印单字符 + 长度 1..4 的 "A" 串 + 一个重复项），
    判定顺序：
      输出长度 == 输入长度            → enc
      stdout 能归一成 0..len 且随输入变化 → check_num
      退出码在 0..len 且随输入变化       → check_exit
      否则                            → none
  - 归一化：`parse_prefix_number` 支持纯数字、prefix=N、correct=N、
    "wrong at N" 中唯一合法数字；check_exit 直接用退出码。
    统一暴露成 `oracle.call(x) -> int`，复用 `solve_prefix_checker`。
  - 结果（连续 3 次一致）：
      E1 纯数字        → check_num  → 解出，322 次探测
      E2 prefix=N      → check_num  → 解出，318 次
      E3 退出码        → check_exit → 解出，337 次
      E4 ELF 变换      → enc        → 解出，123 次（回归 v022）
      N5 只回 wrong    → none       → 拒绝 no_prefix_signal
      N6 恒为 0        → none       → 拒绝 no_prefix_signal
    正样本 4/4，负样本 2/2，平均约 2.3 s/题。
result:
  - **四个关键点**：
    1. **接口不是"能跑"，而是"能给出有序信号"。** 校验器与变换器的区别不在
       输出格式，而在 score(x) 是否满足"前缀越长分数越高"。E1/E2/E3 三种完全
       不同的输出，归一后都是同一个函数，爬坡单元一行不改。
    2. **检测必须要求"分数随输入变化"。** N6 每次都输出合法数字 0，
       如果只看"能不能解析成整数"就会误判成前缀接口；加上
       `len(set(scores)) >= 2` 才能把它拒掉。
    3. **退出码是真实存在的第二信道。** E3 的 stdout 恒为 "wrong"，
       前缀长度只在退出码里。很多比赛校验器就是这样的（`return i`）。
       代价是 0..255 的上限，长 flag 需要程序自己分段。
    4. **检测探测集要包含"可能命中的首字符"。** 只用空串和 "A" 串，
       如果 secret 首字符不是 'A'，所有探测的前缀都是 0，退出码/分数不变化，
       会被误判成 none。所以探测集必须遍历可打印字符，才能看到 score 的分岔。
  - **诚实边界**：
    - 只支持"泄露前缀长度"的校验器。只回正确/错误的校验器（N5）无法爬坡，
      会如实返回 `no_prefix_signal`。
    - 退出码信道只有 8 位；超过 255 的前缀长度需要分段或其他信道。
    - 检测是启发式的：如果 secret 首字符不在可打印集里，可能漏判。
    - ELF 每次探测起一个进程，322 次探测约 4 s；比 Python 校验器慢一个量级，
      但仍是可接受的交互成本。
conclusion:
  - v022 只能把 ELF 校验器当"非变换"拒绝；本版本把它变成了真正的前缀接口：
    检测信道 → 归一成 score → 复用既有爬坡单元。ELF 与 Python 校验器
    在规划器里走同一条 `solve_prefix_checker` 路径。
  - 这条能力与 LAW-0023/0026 一致：不猜逻辑，只利用程序自己泄露的行为信号；
    没有信号时明确拒绝。
next: 支持更复杂的前缀信号（"第几位错"、时间侧信道）；退出码分段；
      把检测探测集做成可配置；在真实 stripped 二进制上压测。
