```yaml
id: LAW-0032
prev: LAW-0031
date: 2026-11-12
source: 实验
topic: 句中断块的根因是"按元素组装块"，不是切句算法；跨元素按句打包才能修好
hypothesis: 检索结果里块尾停在逗号/顿号，是切句器按 token 窗口截断造成的。
experiment:
  - 先换切句器（A/B，同一批 PDF）：
      - 旧：llama_index `SentenceSplitter(chunk_size, chunk_overlap)`；
      - 新：只用标点/空行切句的正则；
      - 结果：三本书的块数完全一致（798/798、1569/1569、673/673），
        块尾分布也一致。**换切句器没有任何效果**。
  - 原因：`chunk()` 是"每个 element 先切好、再 `_merge_small` 合并"，
    而 PDF 解析器会把一句话拆进相邻的多个 paragraph 元素。
    块边界由"合并到 480 token 为止"决定，落在元素边缘；
    切句器只决定元素内部怎么切，管不到元素之间。
  - 逐条分类 614 个可疑块尾：
      - 317 个是段落里的代码/汇编，以 `;` 结尾（语句边界，不算句中断）；
      - 236 个是公式引导语，以 `：` 结尾（自然边界）；
      - 36 个以逗号结尾且正好停在元素边界；
      - 23 个是段落里的代码以逗号结尾；
      - **只有 2 个**是切块器在散文元素内部从逗号处切开。
  - 修复：
      - `chunk()` 改为先生成 `_Unit`（一句话/一行代码/一个表格片段，
        携带来源元素），再统一打包；
      - 同一小节内连续的 paragraph 元素先拼成一条文本流再切句，
        句子可以跨元素，块边界只落在句子之间；
      - 每个 unit 记录命中的元素集合，块的 citation 取并集（页范围仍然正确）；
      - 超长句只在句末标点切；没有句末标点才退到逗号/冒号/空白；
        代码/表格超长时保持按行切，不套用散文标点。
  - 修复后（同一批书，内存中重切）：
      - C++ 反汇编：798 → 661 块，逗号尾 5 → **0**；
      - 加密与解密：1569 → 1302 块，逗号尾 16 → **1**（剩余是十六进制字节数组，
        逗号本身就是数据分隔符）；
      - 从 0 到 1：673 → 599 块，逗号尾 13 → **0**；
      - 这三本 PDF 的块数下降约 17%：边界落在句子之间后，
        不再有元素边缘造成的半空块（全库见下）。
  - 语料级重切（15395 块，原 16362，-5.9%；PDF 类约 -17%）：
      - 散文块尾停在逗号/顿号/左括号（排除元数据行）的：**61 → 11**；
      - 剩余 11 个基本都是十六进制字节数组或嵌在段落里的代码，
        逗号本身就是数据/语句分隔符，不属于"读起来断句"；
      - 以 `;` 结尾的 842 个、以 `:` 结尾的 61 个，抽样全部是汇编/代码语句
        或"证明："这类公式引导语，边界自然。
result:
  - **最关键的一点**：句中断块是**数据组装单位**的问题，不是切句算法的问题。
    在错误的层级上换算法（换掉 llama 的 SentenceSplitter）看起来"修了"，
    实测块边界一个都没变——A/B 必须比对输出，不能只看代码改动。
  - **跨元素拼流**是必要的：PDF 的 element 是版面块，不是段落；
    句子跨块是常态。让句子先跨元素成流、再打包，边界才会落在句子之间。
  - **来源信息不能丢**：跨元素句子同时属于多个元素，
    citation 取并集即可；页范围用 min/max，仍然可回溯。
  - 剩余句中断尾基本只有两类，都属于内容本身：
    十六进制/字节数组（逗号是数据）、代码语句（`;`）。
    这两类不该由切块器"修"，UI 的"载入下一块"继续兜底即可。
  - **ASCII `!`/`?`/`;` 不能无条件切句**：`![alt](url)` 会被切成
    `! [alt](url)`，Markdown 图片语法全部失效（实测块内 0 个合法图片引用）。
    改为只在后接空白或行尾时切；中文 `。！？；` 不受影响。
conclusion:
  - 修切块问题先问"块是在哪个层级拼起来的"。
    按元素拼，就在元素边缘断；按句拼，才在句子边界断。
  - 语义切块（embedding 分组）也走同一条 `_Unit` 流水线，
    只是在句子上多了相似度阈值，结构修复对两种模式同时生效。
```
